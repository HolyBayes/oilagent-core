# Обязательный расчётный модуль (§2.5 DOCX)

Реализованы два метода — ARIMA и ETS — на исторических ценах EIA. Это новый расчёт по временному ряду, а не извлечение чужого прогноза из PDF. Naive last-month считается дополнительно как benchmark и не засчитывается вторым методом.

## Данные и срез

`data/brent_daily.csv` — подготовленный CSV из официального [EIA Europe Brent Spot FOB](https://www.eia.gov/dnav/pet/hist/RBRTED.htm); исходный XLS URL, дата загрузки и SHA256 исходника/CSV находятся в `data/brent_daily.json`. В snapshot 9117 дневных наблюдений, последнее — 2026-10-27. Секреты/API-ключи для ряда не нужны. CSV включён в Git и Docker image как начальное заполнение кеша; сеть используется только для недостающих интервалов.

Целевая величина — среднемесячная Europe Brent spot FOB, USD/bbl. Это не Brent futures, WTI или Urals. Среднее строится по доступным дневным наблюдениям завершённого календарного месяца. Требуются ≥75% будних дней и последняя запись не раньше трёх рабочих дней до конца месяца. Это простое правило доступности, не биржевой календарь: праздники и задержка публикации показываются отдельно. Октябрь 2026 содержит 19 из 22 будних дней, до 27 октября; среднее неполно по всем потенциальным наблюдениям.

`as_of` — ISO-дата, по умолчанию сегодня UTC; будущая дата отвергается. Данные месяца as_of и последующих месяцев исключаются **до** агрегации, обучения и проверки. По умолчанию используются последние 120 завершённых месяцев. Явные `start_date`/`end_date` задают включительный диапазон дневной истории; для моделей берутся целиком входящие в него завершённые месяцы, от 96 до 600, без скрытого обрезания до 120; пробелы, дубликаты, нечисловые/неположительные цены и несовпадение hash дают отказ. История публикационных vintages не восстанавливается: backtest использует скачанную версию наблюдений.

Если snapshot отстаёт от последнего завершённого месяца, `data_end` и даты прогноза остаются настоящими, возвращается `stale_data`. Старые прогнозные месяцы не переименовываются в текущие. Непустой `BRENT_DATA_PATH` включает локальный режим без скачивания; рядом обязателен JSON того же имени с метаданными и hash. По умолчанию используется расширяемый кеш `BRENT_CACHE_PATH=workspace/prices`, отдельный writable mount в compose.

## Кеш диапазонов

Кеш хранит котировки и отдельно покрытые включительные интервалы дат. Если запрошенный диапазон полностью покрыт, расчёт берёт нужные месяцы из кеша без сети. Иначе из диапазона вычитается объединение покрытия и скачиваются только недостающие интервалы — в начале, конце или между участками. TTL и автоматического перескачивания покрытых дат нет; уже сохранённые значения не перезаписываются.

Загрузчик использует публичный CSV [FRED DCOILBRENTEU](https://fred.stlouisfed.org/series/DCOILBRENTEU): тот же дневной ряд Europe Brent spot FOB, источник EIA. `cosd`/`coed` ограничивают запрос недостающими датами. Выходные и пропуски публикации не становятся нулевыми ценами. Неопубликованный хвост после последнего доступного наблюдения остаётся непокрытым и будет запрошен снова.

Сохранение сериализовано файловым lock; CSV/JSON snapshot имеют hash, указатель переключается атомарно. Метаданные сохраняют интервалы, даты загрузок и hash ответов. При сетевой ошибке кеш остаётся доступным, а `data_cache.missing` показывает незаполненные интервалы; недостаточная история не подменяется выдуманными данными. Это кеш наблюдений разных дат загрузки, не архив исторических vintages.

[Реальная HTTP MCP проверка](history-cache-evidence.json): кеш 2016-01-01…2025-09-30 расширен запросом только 2025-10-01…2026-09-30; повторный вызов — `hit`, без сети, результаты моделей совпали. LLM-вызовов: 0.

## Модели, выбор и интервалы

- ARIMA(1,1,0) без drift, на log(price). Фиксированный order, без подбора по test. Номинальный 80% Gaussian prediction interval вычисляет statsmodels на log-шкале, затем границы переводятся в USD/bbl.
- ETS с additive error, damped additive trend, без сезонности, на log(price). Радиус интервала — 80-й квантиль абсолютных log-errors **отдельно для каждого горизонта** по 12 calibration origins. Это небольшой эмпирический интервал, без обещания точной калибровки.
- Точечный прогноз после exp — условная медиана будущей среднемесячной цены, не математическое ожидание логнормального распределения.

Поддержаны h=1..6. Выбор ARIMA/ETS делается по среднему `|actual/predicted−1|` на calibration. Затем 13 отдельных expanding-window test origins измеряют MAE/RMSE, фактическое покрытие и ширину интервалов для каждого горизонта; naive сравнивается на тех же срезах. Последний target calibration доступен к первому test origin, поэтому calibration-интервалы не используют будущие относительно test данные. На текущем snapshot общая граница — апрель 2025. Origins/targets перекрываются: 13 origins не означают 13 независимых экспериментов.

После проверки модели переобучаются на доступном срезе. В ответе есть оба прогноза, benchmark, выбранная модель, период данных, метод интервала, calibration count, coverage и исходный hash. При non-convergence или непригодных данных нет скрытой подмены модели на naive.

На текущем срезе выбор — ETS, но naive немного лучше по средней MAE h=1..6 на отложенном периоде. Coverage ETS составляет примерно 38–69% по горизонту вместо номинальных 80%; ARIMA — примерно 62–92%. Эти результаты сохранены без настройки по test и показаны в предупреждениях. Интервалы не охватывают все геополитические или структурные шоки; это демонстрационный univariate forecast.

## MCP и самостоятельный выбор агентом

Analyst MCP публикует `forecast_brent(horizon_months=3, as_of="", start_date="", end_date="")`. `health.forecast=true` означает наличие вычислительной возможности. Схема горизонта ограничена 1..6, даты дополнительно проверяет сам модуль.

Общий graph извлекает intent/инструмент/горизонт/явный срез одним structured routing-вызовом. Для forecast исполняет вычислительный модуль, не ходит в web, не просит LLM генерировать числа. Markdown-таблица и краткая интерпретация строятся кодом из результата. Вопрос о прогнозе, опубликованном в отчёте, остаётся domain_qa. WTI/другой инструмент требует уточнения. Сценарий сокращения добычи пока остаётся отдельным неподключённым путём; это не ARIMA/ETS-прогноз без дополнительных предпосылок.

Запуск из core/:

```bash
python -c 'from analyst.forecast import forecast_brent, render_forecast; print(render_forecast(forecast_brent(3)))'
python scripts/smoke_ouroboros.py
pytest -q
```

Для повторной подготовки CSV: скачать URL из metadata, открыть XLS `Data 1` через pandas/xlrd с `skiprows=2, names=["date", "price"]`, записать даты как YYYY-MM-DD и обновить SHA256 CSV/исходника и retrieved_at в metadata. Это способ обновления начального CSV. Рабочий кеш расширяется автоматически только для непокрытых дат.

## Реальные проверки

GigaChat получил schema **из настоящего HTTP MCP каталога** и сам выбрал `forecast_brent` при `function_call=auto` (165 токенов); вызов исполнен через стандартный MCP ClientSession. Отдельно HTTP `answer_question` с живым GigaChat сам выбрал forecast route и вернул `forecasted` (410 токенов). Эта первоначальная проверка не запускала полный Ouroboros; последующая проверка его UI описана в [UI.md](UI.md). Оба пути выполнили ARIMA/ETS и вернули одинаковый hash входного snapshot. [Сохранённый результат](forecast-mcp-evidence.json).

Offline HTTP smoke через немодифицированный Ouroboros MCPManager теперь обязательно вызывает `forecast_brent` и проверяет оба метода. `--live` дополнительно требует от общего graph статус `forecasted`, а не старую заглушку. Тесты проверяют оба метода/интервалы, горизонты, hash, invalid data, отсутствие влияния будущих наблюдений и вызов расчёта graph без web/LLM-синтеза.

Более ранняя текущая проверка GigaChat: PDF-ответ с цитатой, сверенной с оригинальным EIA PDF; web вернул `needs_web` из-за DDGSException. [Результаты](gigachat-smoke-evidence.json): 3849 токенов. Forecast-проверка: ещё 575. Сумма этих прямых проверок — **4424 токена**, без последующих расходов native UI и не глобальный расход аккаунта.

Первичные интерфейсы: [statsmodels ARIMA](https://www.statsmodels.org/stable/generated/statsmodels.tsa.arima.model.ARIMA.html), [ETSModel](https://www.statsmodels.org/stable/generated/statsmodels.tsa.exponential_smoothing.ets.ETSModel.html).

## Дополнение 2 ноября 2026

Расчётный модуль дополнен отдельным `supply_cut` tool: P0, Q0 и cut, интервалы отрицательной demand elasticity и неотрицательной supply elasticity, явные пользовательские assumptions. Проверяются finite inputs, cut < Q0, знаки и порядок границ. Цена и объёмы не берутся из фантазии LLM; отсутствующие inputs ведут к уточнению. Результат — conditional sensitivity, не confidence interval и не causal forecast.

`market_quote` возвращает delayed Brent/WTI futures price с timestamp/exchange/unit/type из Yahoo chart metadata. Историческая EIA spot, опубликованный прогноз PDF и биржевая котировка показываются раздельно. Описание типа/задержки источника: [Yahoo Brent futures](https://finance.yahoo.com/quote/BZ%3DF/). Живой вызов и два метода в Linux проверены; примеры — examples/demo_dialogues.md и deployment-evidence.json.

Native UI передаёт canonical forecast result без нового пересказа происхождения данных. Ошибка прежнего UI-прогона исправлена и отдельно проверена: native-delivery-evidence.json. Успех отдельного расчёта не доказывает будущую точность модели; недостаточное ETS coverage и преимущество naive не скрыты.
