# Первый PDF RAG

Проверено 1 ноября 2026 на Python 3.13.2/macOS ARM64. Это завершённый вертикальный срез, не готовый аналитик всего задания.

## Что работает

Два исходных PDF за октябрь 2025: OPEC MOMR и EIA STEO. Скачивание сверяет SHA256 до записи; индексация повторно проверяет файлы. PyMuPDF извлекает текст отдельно по страницам, tokenizer режет его на 400 токенов с перекрытием 60. Пустые страницы отмечаются предупреждениями; OCR отсутствует. Получено 475 фрагментов.

Закреплённый `multilingual-e5-small` строит локальные нормализованные embeddings с `passage:`/`query:`. Chroma хранит cosine index; distance используется только для ранжирования, не как вероятность правильности. Идентификатор корпуса включает manifest, embedding revision и параметры chunking. Повторный ingest того же корпуса переиспользует индекс; указатель переключается после записи всех фрагментов.

Поиск забирает расширенную выборку, оставляет лучший фрагмент каждой страницы. При явном упоминании двух издателей выполняет независимые запросы и чередует результаты перед общим ограничением контекста. Дата публикации сохраняется в provenance; выбора произвольной исторической даты и нескольких выпусков пока нет.

Graph различает вопрос о прогнозе из отчёта и запрос нового расчётного прогноза. Текущие данные требуют web; расчёты и web пока возвращают явный статус недоступности. LLM получает ограниченный контекст и выдаёт claims с ID и дословной цитатой. Код проверяет принадлежность цитаты фрагменту, числовые токены и разрешённую страницу, затем сам строит ссылки. Непрошедшие claims удаляются.

Визуально сверены PDF-страницы EIA 5–7 и OPEC 5, 7. Это ограниченный список для демонстрации, а не сертификат корректности всех чисел страницы. Табличные значения, единицы, периоды и смысл утверждения требуют отдельной оценки: совпадение числовых токенов и цитаты само по себе не исключает неверный пересказ. Автоматического расчёта по PDF-таблицам нет.

## Фактические проверки

- Offline-тесты создают собственные PDF и используют настоящий persistent Chroma с детерминированными тестовыми embeddings. Проверяются provenance, повторная индексация, hash/revision mismatch, пустые страницы, отказ от вымышленных цитат и поведение graph. API не вызывается.
- `python scripts/eval_reports.py` повторяет четыре development-проверки на реальных локальных embeddings. Найдены два нужных EIA-фрагмента; comparison-проверка подтверждает только присутствие двух издателей. В начальном прогоне вопрос OPEC о росте спроса в 2025 возвращал нужную страницу, но фрагмент о другом периоде. Теперь добавляется короткое начало той же страницы, и этот пример проходит; [новая оценка](RETRIEVAL_EVAL.md) сохраняет сравнение и остальные провалы. Не следует представлять эти проверки как качество ответов, holdout или оценку общего retrieval recall.
- Живой сквозной вопрос о прогнозе EIA для Brent в первом полугодии 2026 дал ответ со ссылкой на PDF-страницу 5. Сначала поиск пропустил абзац из-за соседних chunks одной страницы; следующая попытка выявила ошибочную freshness-классификацию. После исправлений третий прогон прошёл. Все результаты сохранены в [rag-evidence.json](rag-evidence.json), включая неудачные, расход 6477 токенов.
- Отдельный компактный native GigaChat function call принял все пять Evolution schemas. Модель создала bounded policy, она исполнена через in-process MCP и прошла synthetic checks; 715 токенов. [schema-probe-evidence.json](schema-probe-evidence.json). Это не запуск Main worker, не HTTP transport probe и не approval/release. Полный дорогостоящий Ouroboros повторно не запускался.
- Совокупный сообщённый провайдером расход этих проверок: **7192 токена**. Это дополнение к ранее сохранённому расходу полного runtime, не глобальный счётчик аккаунта.

## Что осталось

До расширения корпуса нужны development/holdout вопросы с размеченными фактами и проверка смысла ответа. Промах OPEC исправлен контекстом страницы. На девяти заранее закреплённых отложенных вопросах наличие нужных фактов в контексте выросло с 3/9 до 4/9; пять случаев пока не проходят. Набор остаётся открытым и теперь подходит для regression, но не для дальнейшего заявления о blind оценке. Evolution пока не меняет production retrieval: synthetic check и реальная оценка качества должны быть разведены перед human release/rollback.

Web с provenance теперь подключён: [WEB.md](WEB.md). Следующие функциональные срезы: два расчётных forecast-метода и backtest, затем UI и воспроизводимый полный Ouroboros run. Контейнеры и OpenAI/local live-профили в этой проверке не запускались.
